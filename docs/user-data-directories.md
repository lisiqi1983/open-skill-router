# User Data Directories

Open Skill Router uses two kinds of local directories.

## User-Level SkillRouter Home

Default:

```text
~/.skillrouter/
```

On Windows this is usually:

```text
C:\Users\<user>\.skillrouter\
```

Use this directory for data that belongs to the user rather than to one project:

- `cache/`: fetched Skill source cache and remote static-source cache.
- `locks/`: user-scope install lockfiles.
- `feedback/`: local feedback records when enabled.
- `research/`: local-only Skill source research.

The recommended local research directory is:

```text
~/.skillrouter/research/local-skill-research/
```

Suggested layout:

```text
~/.skillrouter/research/local-skill-research/
  source-manifests/
  indexes/
  catalogs/
  analyses/
  notes/
```

This is the right place for personal Skill inventories, local-only source
manifests, generated local indexes, catalog analysis reports, and private
curation notes.

## Project-Level Runtime Directory

Default:

```text
<project>/.skillrouter/
```

Use this only for project-specific runtime outputs, for example:

- `index.json` generated by `skillrouter index`.
- `sources.json` generated by `skillrouter source add`.
- project-specific catalog or analysis files when the project owner wants them
  local to that project.

Do not use a development repository's `.skillrouter/` directory as the long-term
home for personal Skill research.

## Public Repository Boundary

Public manifests and static indexes should include only public, reviewable Skill
source locators and curated metadata. They should not contain private local
paths, personal Skill inventories, generated local research reports, or
unpublished Skill bodies.

If local research produces useful taxonomy rules or scoring insights, publish
the cleaned rule or insight, not the private inventory.
